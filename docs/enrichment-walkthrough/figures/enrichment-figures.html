Illustrative record; the path it takes is the implemented one.

Say it like this: SAP stores a name, a department and a person in three name fields. Enrichment puts each value in the right field, replaces the name with the registry's official one, and records where every value came from.

Figure 2 · system context

Where enrichment runs

Say it like this: The API never touches SAP directly. ADF reads 30 rows at a time from the DATAshaper table, the API enriches them using registries, the web and a model, and the results are merged back into the same table. Address validation and the later phases run after that.

Figure 3 · identifying the organisation

Seven checks between a search hit and a registry id

Say it like this: Registries are authoritative, but their search is not: they return confident wrong answers. So a hit must pass seven checks, all asking one question: is this the same organisation? When in doubt, there is no match, because a wrong id is worse than none.

Figure 4 · the last resort

The last resort reads before it answers

Say it like this: When no registry answers, the pipeline searches, reads three pages, and makes the model copy a name that literally appears in them. Then it asks the registry again. Only a registry hit, or the page confirming the name SAP already had, ships without a flag.

Figure 5 · how much a value is worth

One function decides every confidence

Review flag = Name 1 or Name 2 is low, or any code that asks for review. Two codes are shown but never queue a record: domain-unverified and registry-location-mismatch.

Say it like this: Every value gets one of three confidence words, from one function asking four questions in a fixed order. Doubt beats everything. A registry is trusted on its own; anything else needs a second, independent source, and a model never counts as one.

Figure 6 · when SAP's name was already right

A kept name is not always a doubtful name

Say it like this: Keeping SAP's own name is not a failure. If the organisation's site, a tied domain or Wikidata confirms it, the kept name is verified and nobody reviews it. Only a name that nothing confirms asks a steward to check.

Figure 7 · the website

A website must be tied to the organisation, not just found

Say it like this: Finding a website is easy; proving it belongs to this customer is the work. A domain is accepted only when a registry, a second source, the name, the customer's own email or the site itself ties it to the organisation. Otherwise it still ships, marked as unverified.

Figure 8 · comparing names

Why the name check penalises extra words

Scores computed with the project's rapidfuzz. The pipeline's GLEIF score is token_sort, taken as the higher of the raw score and the score with legal forms (AG, Inc, GmbH…) removed.

Say it like this: token_set asks whether one name is inside the other, so a pension fund scores 100 against its sponsor. token_sort asks whether they are the same name, so extra words cost points. For accepting a legal entity, only the second question is safe.
